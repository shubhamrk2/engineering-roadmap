Where the four languages sit

Before any syntax: understand the axes. Almost every language question in an interview is really a question about one of these two dimensions.

1
Dynamic and untyped is fast to write and expensive to maintain. JavaScript will happily add a number to a string. That flexibility is why prototypes fly and why large JS codebases without TypeScript get scary.
2
TypeScript is a checker, not a runtime. tsc reads your types, shouts at you, then throws every type away and emits plain JavaScript. Nothing about types exists when the code runs. This single fact is the source of half of all TypeScript interview questions.
3
Java pays up front. Compile step, verbose declarations, a JVM to start — in exchange for catching whole classes of bug before deployment and for the best profiling tools in the industry. You need to read it fluently; you do not need to be a Java expert.

Python

The language of the BadgeDesk core service and of everything on Sheet 12. Target: you can write idiomatic Python without looking things up, and explain what the interpreter is doing.

Data model and collections

Everything in Python is an object with a type and an identity. Variables are names bound to objects, not boxes holding values — which explains almost every surprising Python behaviour.

badgedesk/core/collections_tour.py
# Names are labels. Two labels can point at the same list.
sites = ["BLR-01", "BLR-02"]
alias = sites
alias.append("HYD-01")
print(sites)                 # ['BLR-01', 'BLR-02', 'HYD-01']  the original changed too

# The four containers you will use every day
requests = ["req-1", "req-2", "req-2"]        # list  - ordered, changeable
site_ids = {"BLR-01", "BLR-02"}               # set   - unique, fast membership test
request  = {"id": "req-1", "site": "BLR-01"}  # dict  - key to value, ordered since 3.7
window   = ("09:00", "18:00")                 # tuple - fixed, hashable, safe as a dict key

print("req-2" in site_ids)   # False   set/dict membership is O(1)
print("req-2" in requests)   # True    list membership scans, O(n)

# Comprehensions: the idiomatic way to transform a collection
pending = [r for r in requests if r.startswith("req")]
by_id   = {r["id"]: r for r in [request]}
unique  = {r for r in requests}               # {'req-1', 'req-2'}

# Unpacking and starred assignment
first, *rest = requests
print(first, rest)           # req-1 ['req-2', 'req-2']
Red pencil — the mutable default argument

The default value is evaluated once, when the function is defined, and then shared by every call. This is asked in interviews constantly.

the classic trap
def add_site(site, seen=[]):        # WRONG - one list, shared forever
    seen.append(site)
    return seen

add_site("BLR-01")                  # ['BLR-01']
add_site("HYD-01")                  # ['BLR-01', 'HYD-01']   surprise

def add_site(site, seen=None):      # RIGHT
    seen = [] if seen is None else seen
    seen.append(site)
    return seen

Classes, dataclasses and the shape of your domain

BadgeDesk has an AccessRequest. In Python you model it with a dataclass, which gives you a constructor, equality and a readable repr for free.

badgedesk/core/models.py
from dataclasses import dataclass, field
from datetime import date
from enum import Enum

class Status(str, Enum):            # str mixin -> serialises straight to JSON
    PENDING   = "pending"
    APPROVED  = "approved"
    REJECTED  = "rejected"

@dataclass
class AccessRequest:
    id: str
    employee_id: str
    site_id: str
    starts_on: date
    ends_on: date
    status: Status = Status.PENDING
    reasons: list[str] = field(default_factory=list)   # never `= []` here either

    def __post_init__(self):
        if self.ends_on < self.starts_on:
            raise ValueError("ends_on must not be before starts_on")

    @property
    def duration_days(self) -> int:
        return (self.ends_on - self.starts_on).days + 1

    def approve(self) -> None:
        if self.status is not Status.PENDING:
            raise RuntimeError(f"cannot approve a request that is {self.status}")
        self.status = Status.APPROVED

r = AccessRequest("req-1", "e-902", "BLR-01", date(2026, 9, 1), date(2026, 9, 5))
print(r.duration_days)   # 5
print(r)                 # AccessRequest(id='req-1', employee_id='e-902', ...)

Errors, and why you raise your own

badgedesk/core/errors.py
class BadgeDeskError(Exception):
    """Base class - every custom error inherits from this."""

class PolicyViolation(BadgeDeskError):
    def __init__(self, site_id: str, rule: str):
        super().__init__(f"{site_id} refuses this request: {rule}")
        self.site_id, self.rule = site_id, rule

def check(request, policy):
    if request.duration_days > policy["max_days"]:
        raise PolicyViolation(request.site_id, "max_days")

try:
    check(r, {"max_days": 3})
except PolicyViolation as e:            # catch the specific type, never bare `except:`
    print(e.rule)                       # max_days
except BadgeDeskError:
    print("some other BadgeDesk problem")
finally:
    print("always runs - close files, release locks")
Interviewers ask

“What is the difference between except Exception and a bare except:?” A bare except also swallows KeyboardInterrupt and SystemExit, so your service cannot be stopped cleanly. Always catch the narrowest type you can actually handle.

Async, threads, and the GIL

The most valuable Python topic for a backend interview. The rule in one line: async helps when you are waiting; processes help when you are computing.

badgedesk/core/policy_client.py
import asyncio, httpx

async def fetch_policy(client: httpx.AsyncClient, site_id: str) -> dict:
    r = await client.get(f"/sites/{site_id}/policy", timeout=2.0)
    r.raise_for_status()
    return r.json()

async def fetch_all(site_ids: list[str]) -> list[dict]:
    async with httpx.AsyncClient(base_url="http://policy-svc") as client:
        tasks = [fetch_policy(client, s) for s in site_ids]        # nothing runs yet
        return await asyncio.gather(*tasks, return_exceptions=True) # now they all run

policies = asyncio.run(fetch_all(["BLR-01", "BLR-02", "HYD-01"]))
Red pencil

Calling a blocking function inside an async def freezes the entire event loop and every other request the process is serving. time.sleep(2), requests.get(...) and psycopg2 in an async handler are all the same bug. Use asyncio.sleep, httpx, asyncpg — or push the blocking call to asyncio.to_thread(...).

JavaScript

The runtime that Next.js, Express and NestJS all sit on. You cannot understand TypeScript, React or Node until you understand the event loop and closures.

The event loop — the thing everything else rests on

JavaScript has one thread. It never waits. When you call something asynchronous, the runtime hands the work to the host (browser or Node), keeps running, and later pushes a callback onto a queue.

Closures, scope and this

A closure is a function that remembers the variables where it was defined, not where it is called. It is how React hooks, middleware and every “private variable” pattern in JS work.

badgedesk-web/lib/rateLimit.js
// `hits` lives on after makeLimiter returns - that is the closure.
function makeLimiter(maxPerMinute) {
  const hits = new Map();
  return function allow(employeeId) {
    const now = Date.now();
    const recent = (hits.get(employeeId) ?? []).filter(t => now - t < 60_000);
    if (recent.length >= maxPerMinute) return false;
    recent.push(now);
    hits.set(employeeId, recent);
    return true;
  };
}

const allow = makeLimiter(3);
allow('e-902');  // true, true, true, then false

// The loop trap: var is function-scoped, let is block-scoped
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i), 0);   // 3 3 3
for (let j = 0; j < 3; j++) setTimeout(() => console.log(j), 0);   // 0 1 2

// `this` depends on how a function is CALLED, unless it is an arrow function
const service = {
  name: 'badgedesk',
  regular() { return this.name; },            // 'badgedesk'
  arrow: () => (typeof this === 'undefined' ? 'no this' : 'outer this'),
};
const loose = service.regular;
loose();                                       // undefined - `this` was lost
service.regular.call({ name: 'bound' });       // 'bound'

Promises and async/await

badgedesk-web/lib/api.js
async function getRequest(id) {
  const res = await fetch(`/api/requests/${id}`);
  if (!res.ok) throw new Error(`request ${id} failed: ${res.status}`);
  return res.json();
}

// Sequential - 3 round trips, one after another. Usually a mistake.
const a = await getRequest('req-1');
const b = await getRequest('req-2');

// Concurrent - all three start immediately
const [x, y, z] = await Promise.all([
  getRequest('req-1'), getRequest('req-2'), getRequest('req-3'),
]);

// Promise.all rejects if ANY reject. allSettled never rejects:
const results = await Promise.allSettled([getRequest('req-1'), getRequest('bad')]);
results.forEach(r => console.log(r.status));   // 'fulfilled' | 'rejected'

// Timeouts are not built in - you race them
const withTimeout = (p, ms) => Promise.race([
  p,
  new Promise((_, reject) => setTimeout(() => reject(new Error('timeout')), ms)),
]);
Red pencil

array.forEach(async (x) => { await save(x); }) does not wait for anything. forEach ignores the returned promise, so the function finishes before a single save completes. Use a for...of loop for sequential work, or Promise.all(array.map(...)) for concurrent work.

Same runtime, same semantics, one extra step. Every difference below exists only at compile time.

The type features you must be able to use

badgedesk-web/types/domain.ts
// 1. Unions and literal types model states precisely
type Status = 'pending' | 'approved' | 'rejected';

// 2. Interfaces describe object shapes; type aliases can describe anything
interface Employee { id: string; name: string; managerId?: string }
type Ids = Employee['id'][];               // string[]

// 3. Generics: one function, many types, no `any`
async function getJson<T>(url: string): Promise<T> {
  const res = await fetch(url);
  if (!res.ok) throw new Error(res.statusText);
  return res.json() as Promise<T>;
}
const emp = await getJson<Employee>('/api/employees/e-902');   // emp is Employee

// 4. Narrowing: the compiler follows your `if`s
function label(r: AccessRequest): string {
  if (r.status === 'approved') return `approved by ${r.approvedBy ?? 'unknown'}`;
  return r.status;                          // narrowed to 'pending' | 'rejected'
}

// 5. Discriminated unions - the most useful pattern in TypeScript
type Result =
  | { ok: true;  request: AccessRequest }
  | { ok: false; error: string };

function handle(res: Result) {
  if (res.ok) return res.request.id;        // .error does not exist here
  return res.error;                         // .request does not exist here
}

// 6. Utility types save you writing derivative types by hand
type Draft   = Omit<AccessRequest, 'id' | 'status'>;
type Patch   = Partial<AccessRequest>;
type Frozen  = Readonly<AccessRequest>;
type ById    = Record<string, AccessRequest>;
Red pencil — the boundary lie

const emp = await getJson<Employee>(url) does not verify anything. If the API returns {"nmae": "..."} TypeScript still believes it is an Employee, because the check happened at compile time and the data arrived at run time. At every boundary — HTTP responses, JSON.parse, form input, environment variables — validate with Zod and derive the type from the validator, so there is exactly one source of truth.

the correct boundary
import { z } from 'zod';

const EmployeeSchema = z.object({
  id: z.string(),
  name: z.string(),
  managerId: z.string().optional(),
});
type Employee = z.infer<typeof EmployeeSchema>;    // type derived FROM the check

async function getEmployee(id: string): Promise<Employee> {
  const res = await fetch(`/api/employees/${id}`);
  return EmployeeSchema.parse(await res.json());   // throws on a bad shape, at runtime
}
Drill — TypeScript
Is TypeScript faster than JavaScript at runtime?

No. It compiles to the same JavaScript and the types are removed, so runtime performance is identical. It makes developers faster, not programs.

What is the difference between interface and type?

interface describes object shapes and supports declaration merging (you can reopen and extend it, which is how libraries let you augment their types). type can alias anything — unions, tuples, primitives, mapped and conditional types — but cannot be merged. Practical rule: interfaces for object contracts, types for everything else.

What does any cost you, and what should you use instead?

any switches off checking for that value and everything it touches, so it spreads. Use unknown instead: it accepts anything but forces you to narrow before use, which keeps the compiler working for you.

What is strict mode in tsconfig.json and should you use it?

It enables strictNullChecks, noImplicitAny and friends. Yes, always, from day one — strictNullChecks alone eliminates the largest single category of JavaScript production bugs. Retrofitting it onto a large codebase later is painful.

Java — the tour

Two goals only: read Java confidently, and be able to say how it differs from Python when asked. Do not try to become a Java developer in Week 02.

BadgeDesk.java — the same domain in Java
import java.time.LocalDate;
import java.util.List;
import java.util.stream.Collectors;

enum Status { PENDING, APPROVED, REJECTED }

// A record is Java's dataclass: immutable, with equals/hashCode/toString free.
record AccessRequest(String id, String employeeId, String siteId,
                     LocalDate startsOn, LocalDate endsOn, Status status) {

    AccessRequest {                                   // compact constructor = validation
        if (endsOn.isBefore(startsOn))
            throw new IllegalArgumentException("ends_on must not be before starts_on");
    }

    long durationDays() {
        return java.time.temporal.ChronoUnit.DAYS.between(startsOn, endsOn) + 1;
    }

    AccessRequest approve() {                         // returns a NEW record
        if (status != Status.PENDING)
            throw new IllegalStateException("cannot approve a " + status + " request");
        return new AccessRequest(id, employeeId, siteId, startsOn, endsOn, Status.APPROVED);
    }
}

public class BadgeDesk {
    public static void main(String[] args) {
        var requests = List.of(
            new AccessRequest("req-1", "e-902", "BLR-01",
                LocalDate.of(2026, 9, 1), LocalDate.of(2026, 9, 5), Status.PENDING),
            new AccessRequest("req-2", "e-903", "HYD-01",
                LocalDate.of(2026, 9, 1), LocalDate.of(2026, 9, 2), Status.APPROVED));

        // Streams are Java's list comprehension
        List<String> longPending = requests.stream()
            .filter(r -> r.status() == Status.PENDING)
            .filter(r -> r.durationDays() > 3)
            .map(AccessRequest::id)
            .collect(Collectors.toList());

        System.out.println(longPending);               // [req-1]
    }
}
Python thinking

Duck typing — if it has .approve(), it works. One file can hold anything. Errors are exceptions you may ignore. list, dict, set are built into the syntax. Concurrency means asyncio; the GIL blocks true CPU parallelism in threads.

Java thinking

Nominal typing — it works only if it declares the interface. One public class per file, packages mirror folders. Checked exceptions must be declared or caught. Collections come from java.util with explicit interfaces. Threads are real OS threads, so synchronized, locks and the memory model actually matter.

Language fundamentals
Explain the GIL and when it actually hurts you.

The Global Interpreter Lock lets only one thread execute Python bytecode at a time in CPython. It does not hurt I/O-bound work, because a thread releases the lock while waiting on a socket or disk. It completely blocks CPU-bound scaling across threads — for that you need multiprocessing, a C extension that releases the GIL, or another runtime.

What is the output order, and why: sync log, setTimeout(fn, 0), Promise.resolve().then, sync log?

Both synchronous logs first, then the promise callback, then the timeout. Synchronous code runs to completion on the stack; then the entire microtask queue drains; then exactly one macrotask runs. A promise callback always beats a zero-delay timer.

What is a closure and where have you used one?

A function bundled with the scope it was defined in, so it can still read those variables after the outer function has returned. Real uses: the rate limiter above, Express middleware configured with options, React useState setters, and any module-private counter.

Why does this break when you pass a method as a callback?

In a regular function this is bound at call time by how it is called, not where it is defined. Detaching a method loses the receiver, so this becomes undefined in strict mode. Fix with an arrow function, which captures this lexically, or with .bind().

Does adding types to your Python make it faster?

No. CPython ignores annotations at runtime; they are metadata for tools such as mypy, Pyright and Pydantic. Pydantic uses them to validate, which is a runtime cost, not a saving. Types buy correctness and editor support, not speed.

You must add one language feature to a five-year-old JavaScript codebase to reduce bugs. What and why?

TypeScript with strictNullChecks, adopted file by file with allowJs so nothing has to stop. The largest category of runtime errors in long-lived JS is reading a property of something that is null or undefined, and that check finds them statically without rewriting logic.
