The one problem this sheet is built around

Count the ERROR lines per service in a log file. It looks small. It needs every beginner idea in Python, which is why it is both the first diagnostic and the final gate.

1
A log file is just a list of strings. Python reads a file into a list with one string per line. Everything else is deciding what to do with each string. If you can loop over a list of strings, you can process any text file.
2
Split, then index. "a b c".split() returns ["a", "b", "c"]. Counting from zero, the level is parts[2] and the service is parts[3]. This is the same as indexing a std::vector, except Python raises IndexError instead of reading garbage memory.
3
The dictionary is the whole trick. A dict is a notebook: key in, value out. To count things you read the current count (or 0 if the key is new), add one, and store it back. Almost every integration script you will write contains this pattern.
4
Real input is the real test. A function that works on the five lines you typed and crashes on the sixth malformed line is not finished. Week 3 is about making that impossible.
Why a test file instead of an answer key

An answer key lets you check that your solution looks like mine. A test file checks that your solution works, which is what an interviewer and a production system care about. Each exercise in python-lab/ starts as a stub that raises NotImplementedError; your job is to turn every test green. If a test fails, the failure message is the spec, and learning to read it is half of this sheet.

Red pencil — the rule that makes this work

Using an AI to explain a concept or a traceback is fine and encouraged. Using it to write the function body defeats the exercise: the tests will go green and you will have learned nothing, which is exactly the trap you described at the start. If you are stuck, ask for a hint in words, not for the code. Gate 1 on the last Saturday of week 4 is done with no AI and no search, so cheating the lab only delays the day you find out.

Run a file, hold values in names, branch, repeat, and package it as a function. If you have written C++ loops and functions, this week is translation, not learning to program.

Run a file and read an error

Save the code below as lesson1.py and run python lesson1.py in a terminal opened in the same folder. (On Windows, py lesson1.py also works.) There is no compile step: Python reads the file top to bottom and executes each line.

lesson1.py
name = "Shubham"          # no type written: Python decides it is a str
years = 3                 # an int
print(name)
print(years)
print("I have", years, "years of experience")
print(f"{name} has {years} years")      # f-string: put values inside braces
print(years + 2)          # 5
print(name + "!")         # Shubham!

Now the part that matters: break it on purpose. The error is the lesson.

what Python prints for print(name + years)
Traceback (most recent call last):
  File "lesson1.py", line 9, in <module>
    print(name + years)
TypeError: can only concatenate str (not "int") to str
How to read that, bottom up

Last line first. TypeError is the kind of problem, and the sentence after the colon says what happened: you tried to add a number to a string. Then the line above it: line 9 in your file is where it happened. Read the bottom line, find that line number, and fix that one thing. Do not read the traceback top to bottom like a story. A NameError means you used a name that was never defined, which is nearly always a spelling mistake.

Functions

A function takes inputs and returns a value. Returning is not printing: print shows something to a human; return hands a value to the code that called you. Tests can only check what you return.

functions_tour.py
def is_working_hours(hour):
    return 9 <= hour < 18          # a chained comparison; returns True or False

def request_cost(days, rate=100):   # rate has a default
    total = days * rate
    if days >= 5:
        total = total * 0.9         # 10% discount for a long request
    return total

def count_vowels(text):
    count = 0                       # the accumulator pattern
    for ch in text.lower():
        if ch in "aeiou":
            count += 1
    return count

print(is_working_hours(10))         # True
print(request_cost(3))              # 300
print(request_cost(5, rate=200))    # 900.0
print(count_vowels("Badge Desk"))   # 3
Red pencil — print vs return

A function that prints its answer and returns nothing returns None. Your test asserts count_vowels("abc") == 1, gets None, and fails, while the output on screen looks right. If the screen is right and the test is wrong, check whether you used print where you meant return.

Week 2 — lists, tuples, sets and dictionaries

Collections are where Python stops looking like C++. The dictionary, in particular, is the tool you will reach for more than any other for the rest of this roadmap.

Lists, tuples and the aliasing surprise

collections_tour.py
sites = ["BLR-01", "BLR-02"]       # list: ordered, changeable (like std::vector)
sites.append("HYD-01")
print(sites[0], sites[-1])          # BLR-01 HYD-01   (-1 is the last item)
print(sites[1:])                    # ['BLR-02', 'HYD-01']   a slice

window = ("09:00", "18:00")         # tuple: fixed size, cannot be changed
start, end = window                 # unpacking
print(start, end)

alias = sites                       # NOT a copy: two names, one list
alias.append("PUNE-01")
print(sites)                        # ['BLR-01', 'BLR-02', 'HYD-01', 'PUNE-01']
copy = list(sites)                  # a real, independent copy
copy.append("X")
print(len(sites), len(copy))        # 4 5
Red pencil — assignment does not copy

In C++, vector b = a; copies. In Python, b = a makes a second name for the same list. Change one and the other changes. Use list(a) or a.copy() when you want an independent copy. Interviewers love this one.

The dictionary and the counting pattern

A dictionary maps keys to values, like std::unordered_map. Reading a key that does not exist raises KeyError. .get(key, default) reads safely. Counting is always the same three beats: read the current count, add one, store it back.

counting_pattern.py
notebook = {}                                   # empty dict

# one fruit at a time, no loop yet
notebook["apple"] = 1
print(notebook)                                 # {'apple': 1}
notebook["apple"] = notebook["apple"] + 1       # works only because the key exists
print(notebook)                                 # {'apple': 2}

# the safe version for a key that might be new
fruit = "pear"
current = notebook.get(fruit, 0)                # 0 when missing
notebook[fruit] = current + 1
print(notebook)                                 # {'apple': 2, 'pear': 1}

# the same idea in a loop
counts = {}
for item in ["apple", "pear", "apple", "fig", "apple"]:
    counts[item] = counts.get(item, 0) + 1
print(counts)                                   # {'apple': 3, 'pear': 1, 'fig': 1}

for key, value in counts.items():               # iterate keys and values together
    print(key, value)
print("fig" in counts)                           # True   (membership in a dict is O(1))

When the value is a list instead of a number you are grouping: key to list of things.

grouping_pattern.py
requests = [
    {"id": "req-1", "site": "BLR-01"},
    {"id": "req-2", "site": "HYD-01"},
    {"id": "req-3", "site": "BLR-01"},
]
by_site = {}
for r in requests:
    if r["site"] not in by_site:
        by_site[r["site"]] = []          # first time we see this site
    by_site[r["site"]].append(r["id"])
print(by_site)                           # {'BLR-01': ['req-1', 'req-3'], 'HYD-01': ['req-2']}

# setdefault does the "create if missing" step in one call
by_site2 = {}
for r in requests:
    by_site2.setdefault(r["site"], []).append(r["id"])
print(by_site2 == by_site)               # True

Parsing a log line

parsing.py
line = "2026-10-18 09:01:12 ERROR payments Timeout calling gateway"
parts = line.split()
print(parts)                              # ['2026-10-18', '09:01:12', 'ERROR', 'payments', 'Timeout', 'calling', 'gateway']

date, time, level, service, *message = parts   # starred unpacking: the rest goes in a list

print(len(parts) < 5)                     # True  → check the length BEFORE indexing
The three questions from the first diagnostic

1. What if lines is empty? The loop body never runs, so the dict stays {}. 2. What if a line is malformed? Decide what you want (skip it and log a warning is a sensible default), then make the code do it deliberately, by checking len(parts) before you index. 3. Complexity? One pass over n lines, each line O(k) for its length, dictionary updates O(1) on average: O(total characters), space O(number of services). In C++ you would reach for std::unordered_map<std::string,int> and the complexity is the same.

Week 3 — files, JSON, errors, modules, logging

Real input is messy. This week turns code that works on the happy path into code that behaves on purpose when the file is missing, the JSON is broken, or the line is not what you expected.

Exceptions

exceptions.py
def safe_int(value, default=None):
    try:
        return int(value)
    except (ValueError, TypeError):     # name the exceptions you expect
        return default

print(safe_int("12"))        # 12
print(safe_int("12x"))       # None
print(safe_int(None, -1))    # -1

class ConfigError(Exception):
    """Our own error: lets callers catch exactly this problem."""

def require(value, name):
    if value is None:
        raise ConfigError(f"{name} is required")
    return value

try:
    require(None, "API_KEY")
except ConfigError as err:
    print("caught:", err)        # caught: API_KEY is required
Red pencil — the bare except

except: with no type catches everything, including your typos and Ctrl+C. A bug disappears and the program carries on with wrong data. Catch the specific exceptions you can actually handle, and let the rest crash loudly so you see them.

Modules, virtual environments, packages

A module is just a .py file you can import. A virtual environment is a private folder of installed packages for one project, so one project’s versions never break another’s.

Windows PowerShell, inside your project folder
python -m venv .venv                 # create the environment
.\.venv\Scripts\Activate.ps1         # activate; your prompt now starts with (.venv)
python -m pip install pytest         # installs into .venv only
pip freeze > requirements.txt        # record exact versions
deactivate                           # leave the environment
In production

Every real Python project has a requirements.txt (or pyproject.toml) so that anyone, or any build server, can recreate the same environment. “It works on my machine” almost always means an undeclared dependency. If PowerShell refuses to run the activate script, that is an execution-policy setting on your own laptop; use Set-ExecutionPolicy -Scope CurrentUser RemoteSigned on your personal machine only.

Logging instead of print

logging_tour.py
import logging

logging.basicConfig(level=logging.INFO, format="%(asctime)s %(levelname)s %(name)s %(message)s")
log = logging.getLogger(__name__)

def count_errors(lines):
    counts, skipped = {}, 0
    for line in lines:
        parts = line.split()
        if len(parts) < 5:
            skipped += 1
            log.warning("skipping malformed line: %r", line[:40])   # never log whole payloads
            continue
        if parts[2] == "ERROR":
            counts[parts[3]] = counts.get(parts[3], 0) + 1
    log.info("done: %d services, %d lines skipped", len(counts), skipped)
    return counts

print(count_errors(["2026-10-18 09:01:12 ERROR payments Timeout", "garbage"]))
Red pencil — logging secrets

Logs are copied, indexed and kept for years. Do not log tokens, passwords, full request bodies, or personal data. Log identifiers, counts and timings. This habit matters again when you log what an LLM was asked.

Week 4 — classes, types, pytest, Git, debugging

Model things as classes, prove behaviour with tests you write yourself, keep history, and find bugs by method. This is the week that turns exercises into engineering.

Classes and dataclasses

classes_tour.py
from dataclasses import dataclass, field
from datetime import date
from enum import Enum

class Status(str, Enum):
    PENDING = "pending"
    APPROVED = "approved"

class Stack:
    """A plain class. 'self' is the object the method was called on (C++: this)."""
    def __init__(self):                 # constructor
        self._items = []                # leading underscore = 'internal, by convention'

    def push(self, item):
        self._items.append(item)

    def pop(self):
        if not self._items:
            raise IndexError("pop from empty stack")
        return self._items.pop()

    def is_empty(self):
        return not self._items

s = Stack()
s.push(1); s.push(2)
print(s.pop(), s.is_empty())            # 2 False

@dataclass
class AccessRequest:                    # a dataclass writes __init__, __repr__, __eq__ for you
    id: str
    starts_on: date
    ends_on: date
    status: Status = Status.PENDING
    reasons: list[str] = field(default_factory=list)   # never `= []`

    def __post_init__(self):            # runs after __init__: validate here
        if self.ends_on < self.starts_on:
            raise ValueError("ends_on must not be before starts_on")

    @property
    def duration_days(self):
        return (self.ends_on - self.starts_on).days + 1

    def approve(self):
        if self.status is not Status.PENDING:
            raise RuntimeError(f"cannot approve a request that is {self.status.value}")
        self.status = Status.APPROVED

r = AccessRequest("req-1", date(2026, 11, 2), date(2026, 11, 6))
print(r.duration_days)                  # 5
r.approve()
print(r.status.value)                   # approved
Red pencil — the shared default list

def add(item, seen=[]) creates the list once, when the function is defined, and shares it across every call. The second call sees the first call’s items. Use seen=None and create the list inside, or field(default_factory=list) in a dataclass.

Hints are not enforced when the program runs. They document intent, and editors and checkers use them to catch mistakes before you run the code. FastAPI and Pydantic (week 6) turn them into real runtime validation.

pytest from scratch

test_example.py
import pytest

def total_with_discount(days, rate=100):
    total = days * rate
    return total * 0.9 if days >= 5 else total

def test_short_request_has_no_discount():
    assert total_with_discount(3) == 300

def test_long_request_gets_ten_percent_off():
    assert total_with_discount(5, rate=200) == pytest.approx(900)

@pytest.mark.parametrize("days, expected", [(1, 100), (4, 400), (5, 450), (10, 900)])
def test_many_cases(days, expected):
    assert total_with_discount(days) == pytest.approx(expected)

def test_negative_days_is_an_error_we_forgot_to_handle():
    # This test FAILS on purpose: it proves the function accepts nonsense.
    # Fixing the function (raise ValueError) is how a test earns its keep.
    with pytest.raises(ValueError):
        total_with_discount(-1)
Interviewers ask

“How do you know your function is correct?” A test only proves the function works for the inputs the test uses. Good tests cover the normal case, the edges (empty, one item, the boundary value), and the failures (bad input). If I cannot describe a case that would make a test fail, I have not tested anything yet.

Drill — Python fundamentals
What is the difference between print and return?

print writes text to the screen for a human; the function still returns None. return hands a value back to the code that called the function so it can be used, stored, or tested. Tests and other functions can only use what you return. Follow-up: “what does a function with no return statement give back?” None.

Why does b = a not copy a list, and how do you copy one?

Assignment binds a second name to the same object, so changing the list through either name changes it for both. Use list(a), a.copy() or a slice a[:] for a shallow copy. Follow-up: “is that copy deep?” No: nested lists inside are still shared; use copy.deepcopy if you need independence all the way down.

How do you count occurrences of each item in a list without a library?

Loop over the items and keep a dict: counts[item] = counts.get(item, 0) + 1. .get returns 0 for a key not seen yet, so there is no KeyError. Time is O(n), space O(distinct items). Follow-up: “is there a library for this?” collections.Counter, but you must be able to write the loop.

What does with open(path) as f: do for you?

It guarantees the file is closed when the block ends, even if an exception is raised inside it. That avoids leaked file handles, which on Windows can also lock the file. It is Python’s equivalent of RAII for resources.

Why is a bare except: a bad idea?

It catches everything, including programming errors and Ctrl+C, so bugs vanish and the program continues with bad state. Catch the specific exceptions you can handle and let others propagate. Follow-up: “when is catching broadly acceptable?” At a top-level boundary that logs the error with its traceback and then fails or returns an error response.

What is the mutable default argument bug?

Default values are evaluated once when the function is defined. def f(x, seen=[]) shares one list across all calls, so state leaks between calls. Use seen=None and create a new list inside, or field(default_factory=list) in a dataclass.

Your function passes its tests but fails in production. What do you check first?

What input production sent that the tests did not: empty values, missing fields, unexpected types, very large inputs, odd encodings, duplicates. Reproduce with the real failing input (sanitised), add it as a test that fails, then fix the code until it passes. The new test stays forever.

Where do the type hints matter if Python does not enforce them?

They document intent, let editors and checkers like mypy catch mistakes before running, and frameworks such as FastAPI and Pydantic read them to validate input at runtime. So they are optional in plain Python and load-bearing in a typical API codebase.
