BadgeDesk, deployed

The whole target architecture on one drawing. Everything else on this sheet is a zoom into one part of it.

1
The load balancer is the only thing with a public address. It terminates TLS with a certificate from ACM (free, auto-renewing) and forwards to targets by private IP. Nothing behind it has a route from the internet, which means a misconfigured application cannot be reached directly even if its port is open.
2
The NAT Gateway is the single most common surprise on a personal AWS bill. About $32 a month plus per-gigabyte data processing, charged whether or not you use it. It exists so private subnets can make outbound calls — to CCure, to a package registry. Destroy it at the end of every session and let Terraform recreate it.
3
Multi-AZ RDS is not a read replica. The standby serves no traffic; it is a synchronous copy in another availability zone that gets promoted automatically if the primary fails. You pay double for availability, not for capacity. A read replica is a separate feature and is asynchronous.
4
CloudWatch is not optional infrastructure. Without it you have no logs, no metrics and no alarms — and in an interview, “how would you know it broke?” follows every architecture answer. Budget a full day for it in Week 09.

Regions, availability zones and the shared responsibility model

RegionA geography

ap-south-1 is Mumbai. Data does not leave a region unless you move it. Latency between regions is tens to hundreds of milliseconds. Pick one close to your users and stay in it — cross-region traffic costs money and most services are region-scoped.

Availability ZoneA failure domain

One or more physically separate data centres within a region, on independent power and cooling, a few milliseconds apart. Deploying across two AZs is how you survive a data centre failure. This is why every subnet in the drawing appears twice.

Shared responsibilityWhere the line sits

AWS secures of the cloud: hardware, hypervisor, physical access, the managed service internals. You secure in the cloud: IAM policies, security groups, encryption choices, patching your containers, and not putting the database in a public subnet. Nearly every headline breach is on your side of that line.

IAM — the service that says no

Learn IAM before anything else. Every other service asks it for permission, and every confusing AWS error is ultimately an IAM error.

Why Resource: "*" is sometimes correct

Some actions have no resource to scope to — cloudwatch:PutMetricData is one. The right move is not to give up on least privilege but to constrain with a Condition, as above: this role may publish metrics, but only into its own namespace. Learning to reach for conditions (aws:SourceVpce, aws:PrincipalTag, s3:prefix, aws:SecureTransport) is what separates a real policy from AdministratorAccess with extra steps.

Compute — EC2, Lambda and EKS

Three ways to run the same code. The choice is about who manages what, and how the work arrives.

Lambda — the execution model

# --- INIT: runs once per execution environment, not once per invocation ---

RDS

Managed PostgreSQL. You still own the schema, the queries and the indexes from Sheet 06 — AWS owns the machine, the backups and the failover.

Red pencil

RDS applies engine patches during your maintenance window, and a minor version upgrade means a restart — roughly a minute of downtime, or a failover on Multi-AZ. Your application must reconnect automatically rather than staying broken until someone redeploys it. Set pool_pre_ping=True, keep pool_recycle below any idle timeout in the path, and test it by triggering a reboot with failover on purpose. Discovering that your connection pool cannot reconnect during an unplanned failover at 02:00 is a bad way to learn this.

CloudWatch and operating the thing

If you cannot answer “how would you know it broke?”, your architecture answer is not finished.

CloudWatch Logs Insights — the queries you will actually use
# Find one request across every service, using the trace id from Sheet 05.
fields @timestamp, service, level, message
| filter trace_id = "0af7651916cd43dd8448eb211c80319c"
| sort @timestamp asc

# Which endpoints are slowest at p99?
fields @timestamp, route, duration_ms
| filter ispresent(duration_ms)
| stats count(*) as calls,
        avg(duration_ms) as avg,
        pct(duration_ms, 99) as p99 by route
| sort p99 desc | limit 20

# Error rate per minute, to confirm an alarm is real before acting.
fields @timestamp
| filter level = "ERROR"
| stats count(*) as errors by bin(1m)

# The single most useful line in your application: log structured JSON.
#   {"level":"error","service":"core","trace_id":"0af765...",
#    "route":"POST /v1/access-requests","duration_ms":812,
#    "employee_id":"e_10422","error":"connection pool timeout"}
# Insights parses JSON fields automatically. Plain-text logs force you to
# write regular expressions during an incident, which is the worst possible time.

Red pencil — the free-tier traps that still bill

An Elastic IP you allocate but do not attach is charged $3.60/month because it is unattached — the free tier covers one attached to a running instance only. An EBS volume survives the instance you terminated: check for volumes in the available state after every teardown. SSE-KMS on an S3 bucket with a customer-managed key quietly costs $1/month; use SSE-S3. A second RDS instance puts you outside the free tier immediately — 750 hours is one instance, not one per instance. And the free tier is regional-agnostic but account-wide: two t3.micro instances in different regions consume the same 750 hours.

Drill book

Answer out loud. AWS questions reward specificity — name the service and the reason.

AWS
Explain a VPC to someone who has only used a laptop.

A private network inside AWS that you define with a CIDR block, cut into subnets, each pinned to one availability zone. What makes a subnet public is a single route sending 0.0.0.0/0 to an internet gateway — nothing else. Private subnets route outbound through a NAT gateway, and isolated subnets have no default route at all, which is where the database lives. Security groups are stateful firewalls on the resources; route tables decide what is reachable in the first place.

What is the difference between a security group and a network ACL?

Security groups attach to a resource, are stateful so return traffic is implicit, allow only with no deny rules, and can reference another security group as the source — which is what makes them survive autoscaling. NACLs attach to a whole subnet, are stateless so you must allow return traffic on ephemeral ports explicitly, support deny, and are evaluated in numbered order with first match winning. Use security groups for everyday work; NACLs for coarse subnet-level blocking.

How does IAM decide whether a call is allowed?

Deny by default. An explicit deny anywhere — identity policy, resource policy, service control policy, permissions boundary, session policy — wins immediately and cannot be overridden. Otherwise the organisation SCP and any permissions boundary must permit it, and some attached policy must explicitly allow it. No allow means denied.

Why is an IAM role better than an access key?

A role issues short-lived credentials that rotate automatically and are delivered by the environment, so there is nothing to leak into a repository, a log line or a Docker image. Access keys are long-lived, are frequently committed by accident, and are valid until someone notices. For CI the modern answer is OIDC federation, where GitHub Actions assumes a role scoped by a trust policy to one repository and branch, and no credential is stored anywhere.

When would you choose Lambda over a container, and when not?

Lambda for event-driven, short, spiky or intermittent work: the nightly reconciler, S3 upload handlers, queue processing. It scales to zero, so idle costs nothing. Not for sustained high-throughput HTTP traffic, where per-invocation pricing overtakes a container; not for anything exceeding fifteen minutes; not where cold-start latency is unacceptable at p99; and not where the connection-per-invocation model would exhaust a database pool without RDS Proxy in front.

Your Lambda times out talking to RDS. What do you check?

Almost always networking. A Lambda attached to a VPC needs subnets and a security group, and the RDS security group must allow the Lambda's group on 5432. Then check the subnets are private-with-NAT if the function also calls the internet, that the timeout is longer than the query, and that concurrency has not exhausted max_connections — which is what RDS Proxy exists to fix. A Lambda with no VPC attachment cannot reach RDS at all.

How do you handle a large file upload?

Presigned S3 URLs. The client asks the API for permission, the API checks authorisation and returns a short-lived signed URL constrained by key prefix, content type and maximum size, and the browser uploads straight to S3. The bytes never pass through the application, so there is no memory spike, no request timeout on a slow connection and no NAT data charge. An S3 event notification then triggers a Lambda to record the object against the employee.

Multi-AZ or read replica?

Different problems. Multi-AZ is availability: a synchronous standby in another zone that serves no traffic and is promoted automatically on failure. A read replica is capacity: an asynchronous copy you can query, which lags behind the primary. Use Multi-AZ for uptime, replicas for read scaling, and never read your own write from a replica.

What would you alarm on for BadgeDesk, and what would you deliberately not?

The four golden signals: p99 latency above one second sustained, 5xx rate above one per cent, request count dropping to zero, and saturation of CPU, memory, database connections or disk above eighty per cent. Plus business signals such as the provisioning queue depth growing. I would not page on high CPU with healthy latency, or on a single error, because unactionable pages train people to ignore the pager and that is how the real outage gets missed.

Your bill jumped from $5 to $400. How do you investigate?

Cost Explorer grouped by service, then by usage type, over the period where it changed. The usual suspects are a NAT gateway left running, an EKS control plane, orphaned Elastic IPs and EBS volumes, cross-AZ or NAT data transfer, and CloudWatch Logs ingestion from a debug statement in a hot loop. Then fix the process rather than the symptom: budget alarms at multiple thresholds, mandatory cost-allocation tags, and terraform destroy as a habit rather than an intention.
