The shape of the five months

Five phases, in dependency order. Each one is a prerequisite for the next, which is why Python comes before FastAPI and FastAPI before RAG.

1
Gate 1, Saturday 28 Nov. Solve the original log diagnostic cold in 30 minutes: no AI, no search. This is the one gate that matters most. If it fails, you repeat a Python week rather than carry on, because every later phase assumes you can write Python.
2
Gate 2, Saturday 2 Jan. A mock vendor integration that survives timeouts, duplicates and bad signatures, and an explanation of why it is safe to retry. This is the enterprise-integration strength you already have, made provable and explainable.
3
Gate 3, Saturday 30 Jan. Project 1 is public with README, tests and architecture notes, and the first five applications are out. Applications start here because hiring takes weeks and Project 2 is not required to be credible.
4
Gate 4, Saturday 20 Feb. You can build, test and secure a small MCP server and explain it without hand-waving. This is where your existing MCP exposure turns into depth you can defend.
5
The hiring clock. If the first application goes out on 29 January and the process takes four to eight weeks, an offer lands between late February and late March at best. Applying later than February makes a 31 March offer unlikely however well the study goes. That is a property of hiring, not of your ability.

What is realistic

An honest reading of the deadline, so you can decide how to use the plan, not so you can feel good about it.

Red pencil — the assumptions this plan depends on

It assumes about five focused hours a day, every day, for 151 days, alongside your job. That is roughly 750 hours. Most people cannot sustain that without breaks. If you consistently manage three to four hours on workdays, the plan still works, but the end state moves: Project 2 shrinks first, then the interview phase compresses. Decide that deliberately; do not let it happen by default.

Why gates instead of a checklist

A checklist can be completed without learning anything. A gate cannot: it asks you to do something you could not do before, under conditions that make copying impossible. When a gate fails you learn precisely which skill to revisit, which is more useful than a week of ticked boxes.

Pre-startSheet 20

Rules that keep this honest

Constraints you set at the start, written down so they survive a tired week.

BudgetSpend nothing

Official documentation, open-source libraries, local development, synthetic data and mock services. Anywhere a paid LLM API would be the obvious choice, the plan builds behind an interface so a local model or a mock works instead. A service’s free tier can change, so I check the provider’s current terms before depending on one and I say so when I have not.

ConfidentialityNothing from work, ever

No employer or client code, data, credentials, internal names or architecture in any repository, note or demo. Describe past work at the level of what you personally did and learned, never the confidential detail.

OwnershipTell the truth about AI help

For every project, keep a note of what you wrote, what an assistant generated, and how you checked it. In interviews you will be asked; the honest answer with a clear validation story is stronger than an inflated one.

AI useExplain, do not write

Use an assistant to explain concepts and tracebacks and to review your code. Do not use it to write the exercise you are being tested on. Every week one task is done with no assistance at all.

Deliberately not on the plan

Training or fine-tuning models Deep learning mathematics Kubernetes Multiple cloud providers Five agent frameworks Certifications Courses watched without building

If a posting you really want requires one of these, add it then, with evidence from the posting. Not before.

Drill — the plan
Why does the plan start applying in late January instead of waiting until you feel ready?

Hiring takes four to eight weeks from application to offer, and feeling ready is not a measurable condition. Credible evidence is: Project 1 public with tests and a README, and Gates 1 to 3 passed. Waiting for Project 2 would push offers past the deadline. Applying earlier also gives real interview feedback to improve the later weeks.

What do you do if you fail Gate 1?

Repeat a Python week targeting the exact failing skill, then retake the gate. Do not start FastAPI. Every later phase assumes independent Python, and a live-coding round will expose the gap far more expensively than a delayed week does.

Why no Kubernetes or fine-tuning?

Target roles centre on building and integrating applied-AI systems: Python, APIs, databases, retrieval, tool calling, evaluation and reliability. Kubernetes and fine-tuning are deep specialities that rarely decide those interviews and cost weeks. If a specific posting requires one, it gets added with that evidence.

How will you show which parts of your portfolio you wrote?

Commit history showing incremental work, a short ownership note per project (written by me, generated with assistance, how I validated it), tests I wrote myself, and the ability to explain and modify any line live. The honesty is the point: it makes the validation story credible.
